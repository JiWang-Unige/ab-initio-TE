  🤔 关于 One-Hot Baseline 的讨论

  主人提出了一个非常好的问题呢！(｡•̀ᴗ-)✧
  从科学严谨性角度，浮浮酱认为确实需要一个非深度学习的baseline来对比喵～

  📋 为什么需要 One-Hot/K-mer Baseline？

  目前我们的对比是：
  - Baseline: 预训练GLM (无对比学习微调)
  - Fine-tuned: 对比学习微调后的GLM

  但这无法证明：
  1. GLM embeddings是否真的比简单的序列特征好？
  2. 还是单纯因为GLM本身就很强？

  🎯 建议添加的Baseline对比

  | Baseline 类型           | 特征维度  | 说明                      |
  |-----------------------|-------|-------------------------|
  | K-mer频率 (k=4)         | 256维  | 传统方法常用，类似RepeatMasker思路 |
  | K-mer频率 (k=6)         | 4096维 | 更高分辨率的序列组成              |
  | One-hot + CNN pooling | 可变    | 简单的卷积特征提取               |
  | 随机embeddings          | 128维  | 最差情况baseline            |

  📊 预期结论

  如果我们的实验设计正确，应该看到：
  随机 << K-mer << 预训练GLM << 微调GLM

  这样才能证明：
  1. ✅ GLM学到了超越简单序列组成的特征
  2. ✅ 对比学习进一步提升了TE分类能力

  🔍 当前数据配置问题

  1. 样本量确实较小：

  总计:   56,000 条

  2. 序列长度确实固定为512bp：

  从 prepare_cross_species_data.py 的逻辑来看：
  # 长于512bp的TE → 随机截取512bp窗口
  if te_len >= seq_length:
      offset = random.randint(0, te_len - seq_length)
      start = te['start'] + offset
      end = start + seq_length

  # 短于512bp的TE → 从中心扩展到512bp (包含padding)
  else:
      center = (te['start'] + te['end']) // 2
      start = max(0, center - seq_length // 2)
      end = start + seq_length

  这意味着：短于512bp的TE被扩展（包含了周围的非TE序列），可能稀释了TE的信号
  喵！

  🎯 主人的期望 vs 当前实现

  | 方面   | 主人期望         | 当前实现            | 问题              |
  |------|--------------|-----------------|-----------------|
  | 最小长度 | ≥50bp        | ≥100bp          | 丢失了50-100bp的短TE |
  | 最大长度 | 截取到512bp     | 截取到512bp        | ✅ 一致            |
  | 变长序列 | 保留50-512bp变长 | 统一padding到512bp | ❌ 丢失变长信息
    |
  | 样本量  | 尽可能多         | 每类8000          | ❌ 可能不足          |

  📈 为什么增大样本量和保留变长可能提升性能？

  1. 对比学习需要大量负样本：当前每epoch只有100k对，可能不足以学习细微差异
  2. 变长序列包含结构信息：
    - LINE平均长度可能与SINE不同
    - 固定512bp丢失了这种自然的长度分布信息
  3. 短TE被"污染"：100bp的TE被扩展到512bp，412bp都是非TE序列！
