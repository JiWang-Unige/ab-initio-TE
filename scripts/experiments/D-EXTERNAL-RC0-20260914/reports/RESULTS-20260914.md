`-pa 4 -xsmall -gff -species <target>`, and no `-a`; the target species
parameters were *Ornithorhynchus anatinus*, *Strongylocentrotus purpuratus*,
and *Caenorhabditis briggsae*, respectively. Their source status remains
`LABEL_GENERATION_COMPLETED_NOT_SCIENTIFIC_PASS`.

`LINE/SINE/LTR/DNA/RC/Retroposon`. The raw RepeatMasker class/family is kept in

## FamDB coverage diagnosis and the minimum next step

The two sparse Label-A products use the same Dfam 3.9 FamDB overlay and
RepeatMasker 4.2.2.  The recorded commands are `-pa 4 -xsmall -gff
-species Strongylocentrotus purpuratus` and `-pa 4 -xsmall -gff -species
Caenorhabditis briggsae`, with no `-a` and no custom `-lib`; the exact records
are in each product's `RUN_METADATA.txt`.

The FamDB itself is not missing the target partitions.  `famdb.py info` reports
12 present partitions, including partition 16, whose lineage includes
Echinodermata (134,843 consensus sequences; 134,805 HMMs), and partition 15,
whose lineage includes Nematoda (354,084 consensus sequences; 354,046 HMMs).
However, `famdb.py lineage -ad --curated --format totals` returns 14 ancestor / 0
lineage-specific entries for taxon 7668 (sea urchin) and 16 / 0 for taxon 6238
(CB4).  The corresponding uncurated counts are 0 / 3,324 and 0 / 0.  This
matches the RepeatMasker logs, which explicitly say that only curated families
are included.  The curated output contains one SINE family, `LmeSINE1c`
(`DF000001423.1`, `SINE/tRNA-Deu-L2`), plus generic RNA and insertion-sequence
records; it therefore explains the 23 whole-file SINE rows.  The observed
problem is curated/lineage coverage and selection, rather than an absent
partition file.

The active downloaded candidate assets contain the two exact assembly FASTAs
and assembly reports, plus the generated Label-A products.  No independent
official TE GFF/BED annotation for either exact assembly is present in the
active asset tree, so the current `.out` files cannot be replaced by an already
available official truth track.  The immediate, fixed-panel follow-up is a
library-sensitivity annotation on the same four coordinates: for sea urchin,
export the 3,324 uncurated lineage families as a custom Dfam library and run
RepeatMasker; for CB4, acquire an exact-assembly official track or run a
de-novo library builder (RepeatModeler2/EarlGrey) and then annotate with that
library.  Re-score the unchanged panel and threshold, retaining these outputs
as alternate comparator/sensitivity analyses rather than silently replacing
the primary Label-A truth.  CB4 cannot be rescued by an uncurated Dfam export
because its taxon query returned zero such families.  This does not justify
choosing TE-rich windows or calling either species' generalization result
complete.

## Corrected primary scores

Only platypus has a non-empty primary T1 truth denominator in this panel. T1
precision/F1 are intentionally undefined because unlabelled sequence is not a
negative set. The secondary T0 values below are agreement with the sparse
RepeatMasker/Dfam comparator and are not independent biological accuracy.

The callable denominator correction is now applied in the D wrapper and in the
cache-only rescore.  Callable panel sizes are 4,194,304 bp (platypus),
4,192,804 bp (sea urchin; 1,500 non-ACGT bp), and 4,106,348 bp (CB4; 87,956
non-ACGT bp).  Callable T0 `bp_tn` is recomputed as `bp_n - bp_tp - bp_fp -
bp_fn`; full-region metrics retain the original full-panel denominator.  The
corrected summaries were regenerated from the saved probability arrays on
`login1.baobab` (no model load or inference), taking 61.15 s, 48.48 s, and
47.16 s for platypus, sea urchin, and CB4, respectively.  Future large-file
rescoring should be submitted to Slurm.

The CPU timing array `12696616_[0-2]` is now complete with exit `0:0` for all

measurement script.
